# Release Runbook

> Build, sign, and ship the Faazio mobile app.

## 🔑 Signing credentials

- Debug builds use the generated debug keystore (automatic).
- **Release builds are signed with the release keystore in CI** via
  `.github/workflows/release-apk.yml`. Because `android/` is gitignored (regenerated by
  `expo prebuild`), the workflow runs `scripts/restore-keystore.sh` (decodes the keystore +
  writes `keystore.properties` from GitHub secrets) and then
  `scripts/configure-release-signing.sh` (injects the `release` `signingConfig` into
  `android/app/build.gradle` to read `keystore.properties`) before `./gradlew assembleRelease`.
- The keystore file lives at `client/mobile/keystore/faazio-release.keystore` (gitignored).
  **Back it up securely — losing it means you can never update the app on the store.**

> Never commit `keystore.properties` or the `.keystore` file. Both are gitignored.
> The `android/` dir is also gitignored (generated by `expo prebuild`) — release signing is
> re-applied by `scripts/configure-release-signing.sh` in CI.

### GitHub secrets (set once)

The release keystore + signing properties are stored as GitHub repository secrets
(`gh secret set <NAME>`); they are never committed:

| Secret | Value |
|---|---|
| `KEYSTORE_BASE64` | `base64 client/mobile/keystore/faazio-release.keystore` |
| `KEYSTORE_PASS` | value from `keystore.properties` |
| `KEY_ALIAS` | value from `keystore.properties` |
| `ALIAS_PASS` | value from `keystore.properties` |
| `STORE_FILE` | (optional) keystore file name, default `faazio-release.keystore` |

## 🚀 Release a new APK (GitHub Actions + gh CLI)

Release builds are **not** run on a local machine — they build and publish in GitHub Actions,
triggered with the `gh` CLI.

```bash
cd client/mobile
# 1) Bump the version (or pass it to the workflow)
#    edit app.json -> expo.version, e.g. "1.0.2"

# 2) Trigger the CI build + release
gh workflow run release-apk.yml -f version=1.0.2 -f tag=v1.0.2

# 3) Watch it finish
gh run watch

# 4) The signed APK is attached to the GitHub Release v1.0.2
#    (gh release upload --clobber replaces any previous APK on that tag).
```

The workflow: checkout → setup Node 24 + JDK 21 → `npm ci` →
`expo prebuild --clean --platform android` → `restore-keystore.sh` →
`configure-release-signing.sh` → `./gradlew assembleRelease` → upload APK artifact →
`gh release create` + `gh release upload --clobber`.

The built APK is also saved as a `faazio-release-apk` Actions artifact for direct download.

### Local debug build

```bash
cd client/mobile
adb devices                  # confirm a device/emulator
npm run android              # debug build → install → launch
```

`npm run android` produces `android/app/build/outputs/apk/debug/app-debug.apk`.

### Manual local release APK (fallback, not the primary path)

```bash
cd client/mobile
bash scripts/restore-keystore.sh        # requires KEYSTORE_BASE64 etc. env vars
npx expo prebuild --clean --platform android
bash scripts/configure-release-signing.sh
cd android && ./gradlew assembleRelease
```

Output lands in `android/app/build/outputs/apk/release/`.

## 🌐 Google Play (manual)

1. Build the release `.aab` (`./gradlew bundleRelease`).
2. Sign in to [Play Console](https://play.google.com/console/), open the Faazio app
   (package `com.faazio.customer`).
3. **Testing** → create a release, upload the `.aab`.
4. Fill metadata, Content Rating, and Data Safety (note CAMERA + READ/WRITE_EXTERNAL_STORAGE
   permissions and SecureStore token usage).
5. **Rollout** to begin review.

> Existing `client/mobile/docs/PLAYSTORE_RELEASE.md` is the older EAS-based manual —
> EAS (`eas build`) is an alternative to local Gradle if you adopt `eas.json`.

## 🍎 App Store (iOS)

Requires macOS + Xcode.

```bash
cd client/mobile
npm run ios                  # build + run in simulator
npx expo run:ios --configuration Release
```

- Bundle id `com.faazio.customer` (from `app.json` → `ios.bundleIdentifier`).
- Upload via Xcode Organizer / Transporter; then fill App Store Connect metadata.
- Info.plist (via `app.json` `ios.infoPlist`) declares camera + photo-library usage strings.

## ✅ Release checklist

- [ ] `npm run ts:check` and `npm run check:boundaries` pass.
- [ ] Version bumped in `app.json` (`version`); the CI `versionCode` is regenerated by `expo prebuild`.
- [ ] GitHub secrets set: `KEYSTORE_BASE64`, `KEYSTORE_PASS`, `KEY_ALIAS`, `ALIAS_PASS` (keystore backed up).
- [ ] `gh workflow run release-apk.yml` succeeded and the signed APK is on the GitHub Release.
- [ ] Release signed and smoke-tested on a device.
- [ ] Store metadata / data-safety updated.
